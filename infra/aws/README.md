# AWS deployment

This creates billed resources: one EC2 instance, private RDS PostgreSQL and authenticated TLS ElastiCache Redis, private S3, ECR, IAM, Secrets Manager, CloudWatch and a budget alert. The amount in the example is an alert threshold, not an estimate or spending cap. Review `terraform plan` before applying. Use encrypted remote Terraform state; state contains the Redis password. Default region is Mumbai.

1. Install Terraform >=1.5 and AWS CLI. Authenticate to your account using AWS SSO or your standard AWS credentials. Copy `terraform.tfvars.example` to ignored `terraform.tfvars`, set your domain and budget contact, then run `terraform init`, `terraform plan`, `terraform apply` in this directory.
2. Point your domain A record to the `public_ip` output. No SSH port is opened; use AWS Systems Manager Session Manager to administer the instance.
3. In AWS Secrets Manager, put a JSON secret value into the `app_secret_arn` output. Include `DJANGO_SECRET_KEY`, `CREDENTIAL_ENCRYPTION_KEY`, desired provider keys from `.env.example`, `GOOGLE_REDIRECT_URI=https://YOUR_DOMAIN/v1/calendar/callback/`, `TELEGRAM_CHAT_ID`, and `TELEGRAM_WEBHOOK_SECRET`. Generate the Django and Fernet keys locally. Never put secret values into Terraform variables or Git.
4. Build and push the app image from the project root. Set your outputs as shell variables; run `aws ecr get-login-password --region REGION | docker login --username AWS --password-stdin REGISTRY`, `docker build -t REPOSITORY:release .`, then `docker push REPOSITORY:release`. The registry is the host portion of the repository output. Docker Desktop must be running for this step.
5. Transfer `infra/compose.production.yml` and `infra/Caddyfile` to `/opt/lilyleo/` through your chosen SSM transfer procedure. Rename the compose file to `compose.yml`. On the instance, authenticate Docker to ECR with its IAM role. Set `IMAGE_URI=REPOSITORY:release`, `DOMAIN=YOUR_DOMAIN`, and `AWS_REGION=REGION`; run `docker compose pull` and `docker compose up -d` from `/opt/lilyleo`.
6. Create the owner with `docker compose exec web python backend/entrypoint.py python backend/manage.py create_owner YOUR_USERNAME`; the bootstrap loads AWS secrets before the management command, and the password is entered interactively. Visit your HTTPS domain and connect Calendar and pair your desktop in Settings.
7. Set Telegram's webhook with `docker compose exec web python backend/entrypoint.py python backend/manage.py configure_telegram https://YOUR_DOMAIN/v1/telegram/webhook/`.
8. Check `/health/`, CloudWatch logs, worker/Beat container status, reminder delivery, an authenticated report download, and desktop reconnect. Record results in `IMPLEMENTATION_CHECKLIST.md`. Leave live verification pending until these succeed.

Secrets are fetched at container startup; restart app/worker/Beat after rotating a provider key. RDS rotates its managed password automatically; restart the application before the old password expires if connection failures occur. Long-term production should use rotation-aware connection refresh. One Beat process must run at a time. A stopped worker can leave an external action uncertain; the app marks it for manual inspection rather than replaying it.

S3 deletion removes the current file; previous object versions expire after seven days. RDS backups remain for seven days. The personal deployment has a single app host; host replacement can interrupt service. These are documented v1 limits, not high-availability claims.
